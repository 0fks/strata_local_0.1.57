# 검증한 원본 버전을 내 저장소에 반영

vendor/strata는 Git submodule이나 원본 다운로드 링크가 아니라 실제 파일 스냅샷입니다. 원본 저장소가 없어져도 이 소스가 남습니다. 엔진·모델·Python/CUDA/wheels는 별도 자산으로 보존하세요.

업데이트할 때:

1. 원본 저장소가 있을 때 별도 upstream clone에서 fetch하고 대상 커밋을 고릅니다.
2. 대상 커밋을 git archive로 별도 후보 폴더에 내보냅니다. 운영 설치와 현재 vendor를 바로 덮어쓰지 않습니다.
3. 새 엔진을 공식 서명 피드에서 확인하고 별도 경로에 준비합니다.
4. 기존 모델과 설정으로 API·도구·이미지·긴 문맥·메모리·성능·종료/시작을 검증합니다. 새 기본값이 기존 동작을 바꾸는지 확인합니다.
5. 검증 후 vendor/strata를 후보 스냅샷으로 교체하고 manifests/versions.json 및 assets.json을 함께 갱신합니다. source commit, engine manifest 및 모든 파일 해시, Python/CUDA 버전을 기록합니다.
6. 원본 LICENSE·저작권·in-tree notices를 유지하고 tests를 실행합니다. 개인정보/키 검사를 통과한 후 변경분을 커밋합니다.
7. 새 설치 폴더로 설치·검증한 뒤 전환합니다. 이전 설치와 로컬 자산을 하나는 보존합니다.

이 저장소는 운영 설치에 git pull을 자동 실행하지 않으며, 최신 모델로 자동 전환하지 않습니다. 검증한 버전을 사용자가 직접 갱신하는 구조입니다. 원본 코드를 직접 수정한다면 변경 내역도 별도로 기록하세요.
